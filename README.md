# comp_phy_project
A computational study of how light bends, escapes, or gets captured around a Schwarzschild black hole. Using numerical methods such as Runge–Kutta, Euler integration, and bisection, the project models photon trajectories and investigates the critical impact parameter and gravitational light deflection..
Light at the Edge of Darkness A numerical study of how a black hole bends and captures light Computational Physics project write-up 1 What is this project about? (plain language) A black hole is a region of space where gravity is so strong that nothing, not even light, can come back out once it gets inside. The boundary of that region is called the event horizon. Light that passes near a black hole but not inside it is not captured, but its path is bent. This bending is called gravitational lensing. We study one clean question: A ray of light comes in from far away, travelling in a straight line that would miss the black hole by a distance b. For which values of b does the ray escape, for which is it captured, and by how much is it bent when it escapes? The distance b is called the impact parameter. It is the perpendicular distance between the incoming straight line and the centre of the black hole. We measure lengths in units of M = GMBH/c2, which is a length (about 1.5 km for a black hole of one solar mass). In these units G=c=1. Model used. A non-rotating, uncharged (Schwarzschild) black hole in empty space. Light is treated as a ray moving along a path called a null geodesic in this fixed spacetime. There is no gas, no accretion disc and no spin. We do not solve Einstein’s field equations; we only follow light in the known solution. Why this is a computational problem. The ray equation is nonlinear and has no solution in elementary functions. The exact bending angle can be written as an integral, but that integral does not give a simple formula for the paths, for the capture boundary or for what happens when b is close to the capture value. A computer lets us trace the rays, find the capture boundary, and measure the errors of the method. It does not have a solution in elementary functions. Exact results exist only as integrals or elliptic functions, which themselves need numerical evaluation. The weak-field formula 4M/b is an approximation and fails badly in the strong-field region (Table 2). To see the paths, and to find out which rays are captured and which escape for any b, we must follow each ray step by step. Near bc the ray is extremely sensitive: a tiny change in b changes how many times it circles. We need numerical event detection and a careful search for bc. Numerical answers have errors. A computational study has to measure them (step size, finite start and end radii, rounding) and compare with an analytic benchmark. That is the scientific content of this project. 4 Computational methods 4.1 Fourth-order Runge–Kutta (RK4) Define v = du/dϕ. Then Eq. (4) becomes two first-order equations du dϕ =v, dv dϕ =3Mu2−u. We wrote RK4 by hand (no library ODE solver) and also wrote the simple Euler method, yn+1 = yn +hk1 (global error O(h)), for comparison. 4.2 Starting the ray correctly Each ray starts at a large radius r0 with u0 = 1/r0 and ϕ0 = arcsin(b/r0) (the position of a straight line at height b). The starting slope is not chosen freely: it is taken from the conservation law, v0 = + 1/b2−u2 0+2Mu3 0. The positive sign means the ray is moving inward (u increasing as ϕ increases). This makes the ray carry exactly the intended b. 4.3 Deciding the fate of a ray (event detection) ˆ ˆ ˆ Captured: u ≥ 1/(2M), i.e. the ray reaches r = 2M. Escaped: v < 0 (moving outward) and u ≤ 1/rmax, i.e. it has reached a large outer radius rmax. Unresolved: neither happens before the total angle reaches a set limit (40π). Such a ray is not called captured or escaped, and no deflection is reported for it. Because RK4 moves in jumps of size h, the ray usually overshoots the boundary. The code then finds the exact crossing inside the last step by bisection. This matters: without it the order of accuracy is lost (Section 5.4). A finite computation cannot prove that a ray stays near the photon sphere forever. It can only say what the ray did in the allowed range. 4.4 Finding bc by bisection We start with b = 4M (captured) and b = 7M (escaped). We repeatedly take the midpoint, trace that ray, and keep the half that still contains the change from captured to escaped. After 60 halvings the bracket is about 10−15 wide. The result is compared with 3√3M. 4.5 Measuring the deflection The ray is started at r0 and stopped at rmax, not at infinity. A straight line between the same two radii would sweep π −arcsin(b/r0) − arcsin(b/rmax). The measured bending is therefore α =ϕend −π+arcsin(b/rmax), (using ϕ0 = arcsin(b/r0)). We check how much error the finite r0, rmax still leave behind. 4.6 Benchmark (13) The exact integral above is evaluated with Simpson’s rule, after the substitution u = um(1−s2) that removes the singularity at the turning point. The turning point um is found by bisection. Changing the number of Simpson points from 1000 to 4000 changes the result at b = 8M by only 3×10−12, so the benchmark is accurate to about 10−11. How reliable is the capture/escape decision close to bc? The numerical method has its own tiny error, which shifts the numerical bc (Table 1). A ray with b = bc(1 − 10−9) is truly captured, but with h = 0.05 the program wrongly reports it escaped (the numerical threshold is 7 × 10−8 too low); with h = 0.01 and 0.002 it is correct. At b = bc(1−10−11) only h = 0.002 is correct. So the classification is trustworthy only for |b − bc| larger than the numerical shift of bc for that step size. The angle limit also matters: for b = bc(1+10−6) the ray must sweep about 16.6 rad (5.3π). With limits of 2π,...,5π the program returns “unresolved” and with 6π it returns “escaped”. This shows that “unresolved” is a real outcome, not a hidden label. 5.7 Other checks ˆ ˆ With the mass set to zero the code must give no bending: result 2.9 ×10−13 rad. We follow rays in a fixed known spacetime; we do not solve Einstein’s equations. Wetrace light rays only. We do not make a telescope image of a real black hole. The observed ring-shaped shadow in real data (for example, [4]) is related to bc, but producing such an image needs much more work. Rays start at a finite radius, not at infinity. The resulting error is measured above and is small for our settings. Close to bc the answer depends on step size (see above). A finite calculation cannot prove that a ray would stay near r = 3M forever. The physics here is standard and well known. The contribution of the project is the implementation, the validation and the error analysis, not new physics.
